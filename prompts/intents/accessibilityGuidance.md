# Intent | Accessibility Guidance

Use this intent when the user asks about keyboard interaction, focus, ARIA,
contrast, screen readers, touch targets, labels, disabled states or inclusive
interaction behavior.

Expected behavior:
- Name the concrete barrier or risk first.
- Connect the guidance to the documented component, pattern, token or rule.
- Give implementation guidance that can be acted on.
- Include at least one practical test using keyboard, a screen reader, zoom,
  contrast measurement or touch target inspection when relevant.
- Distinguish documented requirements from reasonable inference.
- Include state behavior for loading, error, disabled and success when relevant.

Do not reduce accessibility to ARIA attributes. Native semantics, keyboard,
focus, visible state, content and testing are part of the answer.
