# Intent | Pattern Guidance

Use this intent when the user asks how to structure a screen, flow, workflow or
larger interaction model.

Expected behavior:
- Identify the pattern that best matches the user's workflow.
- Explain the structure of the pattern and why it reduces cognitive load.
- Name component adjacencies when useful: which components naturally compose
  with the pattern.
- Include when not to use the pattern.
- Make trade-offs explicit: flexibility vs standardization, density vs clarity,
  exploration vs guided completion, speed vs governance.
- For full pattern inventories, list every official pattern returned by the
  registry and group them by workflow role.

Patterns are architectural composition rules. Do not reduce them to visual
layout tips.
