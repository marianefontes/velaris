# Response Template | Migration Advisor

Use this structure for migration answers:

1. Diagnosis — what is legacy/custom and what is being replaced.
2. Recommended component or approach — name the Velaris target when possible.
3. Reasons — why the target is a better fit (support, accessibility, consistency,
   maintenance, governance).
4. Migration path — numbered steps across discovery, mapping, replacement,
   validation, rollout and monitoring.
5. Risks — visual, behavioral and testing impact.
6. Complexity — Low / Medium / High with one-line justification.
7. Perspective focus — tailor one short paragraph to the active profile.

When the request is broad (interface modernization, custom-to-catalog strategy),
prioritize inventory, equivalence mapping, rollout waves and governance.

Never end with evidence insufficient. If context is missing, ask for the
artifact and still provide the framework.
