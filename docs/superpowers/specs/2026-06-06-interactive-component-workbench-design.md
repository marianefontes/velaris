# Interactive Component Workbench

## Goal

Extend the state synchronization architecture from Button to all 25 documented
components while preserving the current `ComponentsPage` catalog, layout, visual
identity, and RAG extraction contract.

The Button intent contract changes from:

```ts
"primary" | "secondary" | "destructive"
```

to:

```ts
"primary" | "secondary" | "positive" | "negative"
```

`destructive` is removed from the Button documentation, preview, parser, tests,
and generated snippet.

## Shared Workbench Model

Every component receives one valid playground configuration:

```ts
interface ComponentPlaygroundConfig {
  state: string;
  intent: string;
}
```

The selected configuration is the source of truth for:

- active State control;
- active Intent control;
- preview rendering;
- generated snippet;
- snippet parsing and synchronization.

Configurations are stored per component so switching documentation entries does
not discard prior playground choices.

## Controls

State and Intent labels become native buttons for all 25 components.

Each control:

- exposes `aria-pressed`;
- has a minimum 44px target;
- supports keyboard interaction;
- has visible focus;
- updates the preview and generated snippet immediately.

## Preview Contract

`InteractivePreview` receives the selected state and intent plus a callback for
preview-originated state changes.

Each component maps its documented states to meaningful behavior. Examples:

- Toggle controls checked, focus, and disabled.
- Checkbox controls unchecked, checked, indeterminate, focus, and disabled.
- Inputs control empty, filled, focus, error, and disabled.
- Modal controls closed, open, submitting, error, and disabled.
- Data Table controls sorting, selected rows, empty, and loading.
- Feedback components control semantic severity and lifecycle.
- XAI components control confidence, source coverage, audit progress, and
  conflict states.

Intents alter labels, content, options, emphasis, or usage context rather than
inventing unsupported component props.

Preview interactions update the same parent configuration whenever the
interaction represents a documented state change.

## Snippet Synchronization

Each component has a deterministic snippet generator for every documented
state/intent combination.

The snippet editor remains fully bidirectional for Button through its restricted
prop parser. Other components use conservative finite-contract parsing:

1. normalize the edited snippet;
2. compare it with every valid generated state/intent combination;
3. update controls and preview when a valid combination matches;
4. retain the last valid preview and show an inline error otherwise.

This makes every snippet editable without introducing a JSX parser or accepting
unsupported APIs.

## Button Semantics

Button visual intents:

- Primary: principal action hierarchy.
- Secondary: supporting action.
- Positive: successful, confirmatory, restorative, or completion action.
- Negative: critical, destructive, or irreversible action.

Positive consumes the existing success semantic color. Negative consumes the
existing error semantic color.

The previous Do/Don't guidance is updated to name Positive and Negative
explicitly.

## Token Consumption

The preview uses existing Aetheris contracts:

- primary and secondary semantic colors;
- success for Positive;
- error for Negative;
- focus ring and focus border;
- hover, disabled, selected, and feedback contracts;
- 44px minimum target;
- existing motion timing.

Existing semantic CSS variables are exposed at `:root` without changing their
documented values.

## Validation

- all 25 components expose interactive state and intent controls;
- each control changes preview and snippet;
- valid snippet edits synchronize controls and preview;
- invalid snippets preserve the last valid preview;
- Button supports Primary, Secondary, Positive, and Negative;
- no Button `destructive` intent remains;
- every control and interactive preview target is at least 44px where applicable;
- disabled, focus, loading, semantic feedback, and XAI states remain perceptible;
- other preview interactions continue to work;
- mobile has no page-level horizontal overflow;
- Playwright exercises all 25 entries;
- RAG dump and vector collection contain the updated Button guidance.

## Scope Boundary

This work does not create production component implementations or a generic JSX
runtime. It upgrades the documentation playground and uses deterministic
component-specific contracts.
